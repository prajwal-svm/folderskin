# AIアシスタント

FolderSkinは、言葉の説明からスキンを生成できます。方法は2つあります。

- **ローカルモデル**は、あなたのコンピュータ上で無料で描きます。一度セットアップすれば（FLUX.2 [klein] 4B。ダウンロードはMacで4.6GB、それ以外で5.2GBです）、オフラインで動き、キーは不要で、どこにも何も送りません。macOS 14以降のAppleシリコン搭載Mac、WindowsとLinuxのPCで動きます。
- **自分のキーを使う**場合は、すでにアカウントを持っているプロバイダのAPIキーを貼り付けます。キーはコンピュータ上の非公開のファイルに保存され、FolderSkinはあなたのコンピュータからそのプロバイダと直接やり取りします。

どちらを使うかは**設定 → AIプロバイダ**で選びます。チェックマークは、ローカルモデルがセットアップ済みであること、またはプロバイダにキーが設定されていることを示します。

![設定のAIプロバイダ画面。ローカルモデルと7つのプロバイダが並び、それぞれにチェックマークか「キーなし」が付いていて、その下にこのコンピュータのモデルが表示されている](../images/ai-providers.webp)

FolderSkinのサーバも、プロキシも、同梱のキーも、FolderSkinが費用を肩代わりする無料枠もありません。キーを使う場合、**生成**を押すまでは何も送信されません。送られるのは、FolderSkinがあなたの言葉から書いたプロンプト、形に必要なサイズ、そしてそれに添える画像です。フォルダ全体を描く場合は、FolderSkin自身が用意したそのフォルダの空のテンプレートが先に入り、そのあとに追加した参照画像が続きます。

## キーの保存場所

キーは暗号化され、FolderSkin専用のフォルダに、あなたのユーザアカウントだけが読める形で保存されます。

| | |
|---|---|
| macOS | `~/Library/Application Support/app.folderskin.desktop/keys.json` |
| Windows | `%APPDATA%\app.folderskin.desktop\keys.json` |
| Linux | `~/.config/app.folderskin.desktop/keys.json` |

キーは書き込む前にAES-256-GCMで暗号化されます。暗号鍵は、`keys.json`の隣にある`keys.secret`のランダムな秘密値と、このコンピュータのハードウェアIDから（HKDF-SHA256で）導出されます。そのため`keys.json`だけでは何もわからず、2つのファイルを別のコンピュータにコピーしても、そこでは開けません。新しいコンピュータでは、キーをもう一度入力してください。どちらのファイルも所有者だけが読み書きできる権限（0600）で作られ、アトミックに書き込まれます。ただし、すでにあなたの権限で動いているプログラムは両方のファイルを読めてしまい、これはどんなファイルでも防げません。防げるのはシステムのキーチェーンだけですが、その場合は後述のパスワード入力が必要になります。

システムのキーチェーンを使わない理由は次のとおりです。macOSは、キーチェーンに保存した項目を、保存したアプリの署名と厳密に結び付けます。オープンソースのビルドは署名なしかアドホック署名であることが多く、再ビルドやアップデートのたびに別のアプリと見なされて、ログインパスワードを何度も求められてしまいます。ダウンロードしたばかりのアプリからパスワードを求められると、まさに悪意のあるアプリのように見えてしまいます。そこでFolderSkinは、キーチェーンをまったく使いません。

キーはリクエストの瞬間にだけ読み込まれ、エラーメッセージに含まれることも、アプリのウィンドウに返されることもありません。プロバイダのダイアログで**キーを削除**を押すとファイルから削除され、`keys.json`を削除するとすべてのキーが消えます。

## 絵の使いみち

絵はどれも、ある形に向けて作られます。入力欄の下、モデル名の横にあるチップが、どの形かを小さな絵で示します。別の形を選ぶには、チップをクリックするか、入力欄で @ を入力します。

- **Macのフォルダ**：Finderに表示されるままのFolderSkinのフォルダ。
- **Windowsのフォルダ**：Windowsが描くフォルダ。
- **自由形アイコン**：マスコット、もの、キャラクターなど、まわりにフォルダのない単独のもの。どのフォルダにもそのまま付けられます。

@ のあとに名前の一部（`@win`など）を入力してReturnキーかTabキーを押すか、形をクリックします。チップが切り替わり、@ の付いた言葉は入力欄から消えます。新しいチャットは、フォルダパネルがスキンを載せて表示しているフォルダの形で始まります。

形はチャットごとに決まります。それぞれの絵は送信したときに選ばれていた形で作られ、以前のチャットは最後の絵の形で開き、スキンはその形向けに作ったものとして保存されます。形によって、プロンプト、テンプレート、サイズ、結果の切り抜き方が決まります。これはどのプロバイダでも、ローカルモデルでも同じです。

## 絵だけか、フォルダ全体か

フォルダの場合、これがいちばん大事な選択ですが、品質の問題ではありません。

**絵だけ**では、モデルにフォルダと同じ縦横比の平面の画像を描かせ（Macのフォルダなら1024 × 960、Windowsのフォルダなら1024 × 800）、FolderSkinがそれを自分のフォルダにはめ込みます。写真を追加するときとまったく同じです。形はFolderSkinが決めるので、どのアイコンサイズでも、すべてのスキンがきれいにそろいます。透明に対応していないプロバイダを含め、どのプロバイダでも使えます。これが既定の方法で、たいていの場合はこれが正解です。

**フォルダ全体**では、モデルにフォルダそのものを描かせ、その画像をコンポジターを通さずにそのままアイコンにします。ピクセル単位で正確な形はあきらめることになりますが、そのかわり、本物の立体感があり、フォルダの上端からはみ出すようなアートワークが手に入ります。

モデルが画像をもとに描ける場合（OpenAI、Grok、Gemini、FLUX.2、そしてローカルモデル）、FolderSkinは自分で用意したそのフォルダの空のテンプレートを、最初の画像として送ります。明るいグレー一色で塗ったフォルダを単色のキーカラーの中央に置いた、フォルダと同じ縦横比で、長い辺が1024ピクセル以内の画像です（`Base::blank`）。プロンプトでは、このフォルダをそのまま描き直し、輪郭、タブ、そのフォルダならではの部分、サイズ、位置を保って、背景はそのまま残すようモデルに指示します。キーカラーの名前はプロンプトに書きません。マゼンタのことを伝えられたモデルは、マゼンタで描いてしまうからです。そのあとFolderSkinは、フォルダ自身の輪郭に沿って絵を切り抜きます。そのため、結果はFolderSkinのシルエットを保ち、絵の色もふちまでそのまま残ります。フォルダの位置や形を変えてしまった絵は、かわりにキーカラーで切り抜きます。追加した参照画像は、それぞれに割り当てた役割と一緒に、モデルが受け取れる枚数までテンプレートのあとに送られます。

**自由形アイコン**は、いつも全体をモデルが描きます。1つの被写体を欠けるところなく正方形の中央に、透明な背景かキーカラーの上に描かせて、切り抜きます。

## 透明部分の扱い

FolderSkinは、選んだモデルに合った方法を使います。

- **アルファに対応**：リクエストで透明な背景を指定し、返ってくるPNGにはすでに透明な背景があります。FolderSkinは透明な余白を切り詰めるだけです。GPT Image 2.5 FlareとSunburstがこの方法です。
- **アルファに非対応**：プロンプトで、単色のキーカラーの上にフォルダだけを描くよう指示します。FolderSkinはそのあとでその色を取り除き、やわらかいふちににじんだキーカラーも取り除いて（切り抜いた画像に色の付いたにじみが出ないようにするための処理です）、余白を切り詰めます。背景が描かれていないことは検出できます。周囲がキーカラーでなければ、モデルが指示を無視したということなので、FolderSkinは壊れたアイコンを適用するかわりに、その画像を自分のフォルダに使うアートワークとして残します。Recraftにはこの色をパラメータ（`controls.background_color`）としても渡すので、どのスタイルを頼んでも背景は単色になります。

キーカラーはマゼンタ（`#FF00FF`）です。フォルダの絵にはまず出てこない色だからです。ただし、Geminiには緑（`#00FF00`）を使います。Geminiは、マゼンタの上に描いた被写体のまわりに、暗い赤みを帯びたふちを残すからです。ピンクや紫にしたいものも、マゼンタで切り抜くと一緒に消えてしまうので、緑を使います。これにあたるのは、ネオン、70年代エアブラシ、ポップアート、シンセウェイブの各スタイルと、FolderSkinが対応しているどれかの言語でピンクや紫を挙げたアイデアです（pink、lilac、rose、rosa、morado、ピンク、보라、粉红など）。ただ、緑は木の葉や野原など、フォルダの絵にもよく出てくる色です。そこで緑の背景は、画像の端までつながっている部分だけを、実際に塗られた緑の色合いを基準にして取り除きます。フォルダの上に描かれた緑はそのまま残ります（`matte::cutout_connected`）。

FolderSkinのテンプレートをもとに描いたフォルダ全体は、どちらの方法もとりません。上で説明したとおり、テンプレート自身の輪郭に沿って切り抜き、フォルダが動いていたときだけキーカラーでの切り抜きに切り替えます。

キーイングのコードは`crates/folderskin-core/src/matte.rs`にあり、マゼンタの背景の上に本当にピンクの被写体がある場合も含めて、ユニットテストされています。

## プロンプト

あなたの言葉が書き換えられることはありません。`crates/folderskin-ai/src/recipe.rs`は、1枚の絵に必要なものを1つのレシピにまとめます。あなたのアイデア、形とその形で保つ部分、スタイル、入れる文字、あなたの画像とそれぞれの役割、そして被写体のまわりに置くものです。そのあと`prompts.rs`が、このレシピをモデルの系統ごとにいちばん伝わりやすい書き方で書き出します。順番はいつも同じで、何を描くか、どんな見た目か、どんな構図か、画像、文字、描かないものの順です。

- **OpenAIとGemini**には、ラベル付きの行（Style、Composition、Lettering、Constraints）で書き、画像はimage 1、image 2のように呼びます。
- **Grok**にも同じように書き、画像はGrokの呼び方に合わせて`<IMAGE_0>`、`<IMAGE_1>`と呼びます。
- **FLUX**（Black Forest Labsとローカルモデル）には、被写体を先頭にした普通の文章で書き、描かないものについての指示は入れません。FLUXにはネガティブプロンプトがなく、避けるよう言われたものを描いてしまうからです。ローカルモデルのプロンプトは、テキストエンコーダが読める400トークンに収め、必要なときはスタイルを表現媒体だけに縮めます。
- **IdeogramとRecraft**には、短いデザインの指示書として書き、文字の指定は前のほうに置きます。
- **Stability**には短いリストで書きます。StabilityとIdeogramには、描かないものをそれぞれのネガティブプロンプトとして送ります（後述）。

効いているのは、スタイルに関する部分ではなく、構造に関する部分です。

- **「絵だけ」用のプロンプト**は、画面いっぱいに広がるひと続きの絵を求め、被写体は大きく中央に置かせ、フォルダのタブで隠れる帯には空や質感だけを描かせます。テンプレートがその部分を切り取ったり曲げたりするからです。Windowsのフォルダでは、左上の角にも何も置かせません。
- **「フォルダ全体」用のプロンプト**は、フォルダのパーツを奥から手前の順に挙げ、そのまま残す部分を指定します。Macのフォルダなら1つだけのタブと淡い色の紙の帯、Windowsのフォルダなら曲線を描く段差です。これがないと、モデルは決まって重なったフォルダや二重のタブを描いてしまいます。
- **「自由形アイコン」用のプロンプト**は、欠けるところのない1つのものを、正方形の中央に切れずに収めるよう求め、まわりに床や風景や枠を入れさせません。
- **参照画像**は、番号と役割で呼びます。モチーフの画像に写っているものは見分けがつくよう同じ姿のまま描かせ、スタイルの画像からは表現媒体、配色、光、質感だけを取り入れて写っているものは使わず、配色の画像からは色だけを使います。
- **描かないもの**は、形とスタイルに合わせて書きます。縁取り、枠、透かし、署名はいつも入れません。文字は頼んだときだけ、スタイルにありがちな定番の要素（木版画の富士山など）はアイデアで求めたときだけ描かせます。写実的なスタイルでは、クリップアートのような見た目も避けます。
- **どのプロンプトにもサイズは書きません**。モデルは文中で読んだピクセル数どおりには描かないので、サイズはリクエスト自体のパラメータで指定します（後述）。

どの系統、どの形についても、要となるフレーズが含まれていることをテストで確認しています。レシピにはバージョン（`RECIPE_VERSION`）があり、スキンがどのレシピで作られたかを示せるようになっています。

## スタイル

入力欄で / を入力すると、30種類のスタイルが5つのグループに分かれて表示されます。写真と3D、素材と工芸、絵画とドローイング、版画と印刷、デジタルとグラフィックです。名前の一部を入力すると、一覧を絞り込めます。スタイルはあなたの言葉の中には入らず、入力欄の横にある専用の枠に入ります。そのため、アイデアは一字一句そのままで、スタイルはそのあとに付け加えられます。外すには、枠の×をクリックします。

各スタイルは`crates/folderskin-ai/src/styles.json`の1項目で、アプリも、コマンドライン（`folderskin ai styles`で一覧を表示できます）も、プロンプトを書く部分も、すべてこのファイルを読みます。1つの項目には、スタイルの名前、1行の説明、プロンプトでそのスタイルを表す言葉（まず表現媒体、続いて技法、光、色、質感で、作家の名前は決して使いません）、文字の描き方、頼まなくても描き加えがちなもの、結果が満たすべき3つの条件、そしてプロバイダ独自のプリセットがある場合はそのプリセット（Stabilityのスタイルプリセットと、Ideogramのスタイルプリセットまたはスタイルタイプ）が入っています。以前のバージョンのスタイル名も、そのまま使えます。`travel`は旅行ポスター（`screenprint`）に、`ukiyoe`は木版画に、`diorama`はミニチュア風写真になりました。

同じメニューには、出発点になる**アイデア**（どれも題材だけで、スタイルは付きません）と**マイプロンプト**もあります。新しいチャットで入力欄の下に並ぶスタイルボタンも、同じしくみです。クリックするたびに入力欄に別のアイデアが入り、そのボタンのスタイルが枠に入ります。

## 文字入れ

スキンに入れたい言葉は、かぎかっこや引用符で囲みます。たとえば、*地図を読むキツネ、「ESCAPE」の文字入り*のように書きます。FolderSkinは、囲んだ言葉をそのとおりに1回だけ、そのスタイルならではの文字で、形に合わせた位置に描かせます。指示を読み取るモデルには、1文字ずつのつづりも伝えます。フォルダでは前面パネルの中央を横切るように入れ、自由形アイコンではそのものの表面かその下に入れます。囲んだ言葉がなければ、プロンプトは文字をいっさい描かないよう求めます。長い文章はいまも崩れてしまうので、短い言葉を1つか2つにとどめてください。

## マイプロンプト

/ のメニューにある**プロンプトとして保存**を使うと、入力欄の内容をスタイルと一緒に、付けた名前で保存できます。それ以降は**マイプロンプト**に並び、選ぶと入力欄とスタイルの枠にもう一度入ります。すでに使われている名前を入力すると、そのことを知らせたうえで、そのプロンプトを置き換えます。自分のプロンプトの横にある×を押すと削除され、そのあと数秒間は**元に戻す**で取り消せます。

保存したプロンプトは、`skins`フォルダの隣にある`skills.json`に（場所は[ARCHITECTURE.md](../ARCHITECTURE.md#saved-skins)にあります）、`crates/folderskin-ai/src/skill.rs`が定める`folderskin.skill/1`形式のスキルとして保存されます。スキルは、絵に何が描かれるか（`idea`）と、どう見えるか（`base_style`、または独自の`treatment`、`palette`、`light`）を分けて持つので、保存した1つの見た目をどんなアイデアとも組み合わせられます。スキルは書き込む前に毎回チェックされます。確かめるのは、60文字以内の名前と保存する中身があること、スタイルがFolderSkinにあるものであること、独自の`treatment`が8〜60語で、しないことではなくすることをモデルに伝えていること、そしてスキル全体が4KBに収まることです。スタイルとして誰かの名前を挙げたプロンプト（「in the style of」や「by」のあとに名前を書いたもの）は、ひとこと知らせてから保存します。技法を説明するほうがうまくいくからです。

## 参照画像

プロンプトに追加した画像は、指定しなければ**モチーフ**として使われます。画像のチップをクリックすると、**スタイル**（見た目だけを合わせ、写っているものは使いません）か**配色**（色だけを使い、ほかは使いません）に変えられます。画像はテンプレートのあとに、この順番でモデルに送られ、プロンプトではそれぞれを番号と役割で呼びます。

## 各プロバイダに送る内容

`crates/folderskin-ai/src/request.rs`は、どのリクエストも、各プロバイダのAPIリファレンスに書かれているとおりに組み立てます。プロバイダに公式のSDKがあれば、それとも突き合わせて確認しています。テストでは、リクエストを1つずつ、フィールド単位で確かめます。さらに`crates/folderskin-ai/tests/providers.rs`のテストは、すべてのリクエストを、あなたのコンピュータ上でプロバイダの代わりをするサーバに送ります。このサーバはプロバイダのドキュメントどおりに応答するので、メソッド、アドレス、キーを載せるヘッダ、コンテンツタイプ、すべてのフィールドを、実際に送られる形のまま確認できます。

設定値はプロバイダごとのパラメータで渡し、プロンプトの文章には書きません。サイズは形に合わせたもの（アートワークはMacのフォルダなら1024 × 960、Windowsのフォルダなら1024 × 800、フォルダ全体はそのフォルダ自身の形、自由形アイコンは正方形）です。任意のサイズを受け付けるプロバイダにはそのまま送り、そうでないプロバイダには、用意されている中で最も近いサイズかアスペクト比で送ります。

| プロバイダ | リクエスト | サイズ | ほかに送るもの |
|---|---|---|---|
| OpenAI | `images/generations`へのJSON、または`images/edits`へのフォーム（画像はそれぞれ`image[]`として送る） | そのまま、ただし16ピクセル単位（1024 × 960） | `quality`：Flareはhigh、Sunburstはmax、GPT Image 2はmedium。料金が事前にわかるようにするためです |
| xAI Grok | JSONのみ。画像はdata URLとして含める（`image`、複数なら`images`） | 最も近い`aspect_ratio`、またはテンプレート自体の枠 | |
| Google Gemini | `generateContent`へのJSON | `generationConfig.imageConfig`：1Kと、最も近い`aspectRatio`またはテンプレートの枠 | `responseModalities: ["IMAGE"]` |
| Black Forest Labs | JSON。画像は`input_image`、`input_image_2`のように含める | そのまま、1メガピクセル以内（FLUX.2は、1メガピクセルに満たない分も1メガピクセルとして課金するため） | プロンプトの書き換えをオフ（`disable_pup`、flexでは`prompt_upsampling: false`） |
| Recraft | JSON | V4.1のサイズ一覧で最も近いもの | PNGでの出力と、`controls.background_color`としてのキーカラー |
| Stability AI | フォーム | 最も近い`aspect_ratio` | ネガティブプロンプトと、スタイルに対応するものがあればスタイルプリセット |
| Ideogram | フォーム | 3.0の解像度で最も近いもの（1024 × 960） | Magic Promptをオフ、ネガティブプロンプト、スタイルタイプまたはプリセット |

ネガティブプロンプトは、文字（文字入れを頼んだ場合を除く）、透かし、署名に加えて、選んだスタイルが入れがちなものを締め出します。OpenAI、Gemini、Grokにはネガティブプロンプトがないので、同じことをプロンプトの文章で伝えます。

## 提供をやめたモデル

モデルを提供していたころに保存した選択は、そのモデルの後継に移ります。スキンには、それを作ったモデルの名前がそのまま残ります。

| 以前 | 現在 | 理由 |
|---|---|---|
| OpenAI GPT Image 1 | GPT Image 2 | OpenAIが2026年10月23日に提供を終了するため |
| Gemini 2.5 Flash Image | Gemini 3.1 Flash Image | Googleが2026年10月2日に提供を終了するため |
| FLUX 1.1 Pro | FLUX.2 pro | 前の世代で、画像を受け付けなかったため |
| Recraft V3 | Recraft V4.1 | 前の世代で、プロンプトが1,000文字で打ち切られ、FolderSkin自身の指示だけでもそれより長いため |

Ideogram 4.0はまだ選べません。文章で書いたプロンプトをすべて書き換えてしまうからです。FolderSkinは、アイデアをあなたが書いたとおりに保ちます。

## 料金

リクエストはすべて、プロバイダからあなた自身のアカウントに請求されます。生成画面では、ボタンを押す前にモデルのおおよその料金が表示されます。これは、FolderSkinが送る設定値での料金を、プロバイダの料金ページから取ったものです。受け取った画像の分も課金するプロバイダ（xAI、Black Forest Labs）では、フォルダ全体は少し高くなります。各画像の下にある「詳細」には、プロバイダが報告したリクエストの料金（xAI、Black Forest Labs、Recraft）か使用量（OpenAI、Gemini）が表示されます。

FolderSkinは1回押すごとにちょうど1回だけリクエストを送り、勝手にリトライすることはありません。Geminiでときどきあるように（`NO_IMAGE`）、プロバイダが画像なしで終了した場合も同じです。チャットにそのことが表示されて**もう一度試す**が出ますが、リクエストをもう一度送るのは、あなたが押したときだけです。

## ビルドとクロスコンパイル

プロバイダの層はTLSに`rustls`を使っていて、その暗号バックエンド（`aws-lc-sys`）はCのコードをコンパイルします。各プラットフォームのCIランナーでは問題なくビルドでき、FolderSkinのリリースもこの方法で作っています。あるデスクトップOSから別のOS向けにクロスコンパイルする場合（たとえばMacで`cargo check --target x86_64-pc-windows-msvc`を実行する場合）は、ターゲット向けのCのクロスツールチェーンが必要で、ないと`aws-lc-sys`のビルドスクリプトで失敗します。ワークスペースのそれ以外の部分は、ツールチェーンなしでもクロスチェックできます。

## 表示されるエラーメッセージ

| メッセージ | 何が起きたか |
|---|---|
| 「add your … API key first」 | そのプロバイダのキーが保存されていません |
| 「that key was rejected by …」 | プロバイダにキーを拒否されました |
| 「… is rate limiting you right now」 | 429です。しばらく待ってから、もう一度試してください |
| 「… finished without painting a picture」 | プロバイダが画像なしで、理由も示さずに応答しました（Geminiの`NO_IMAGE`）。もう一度試すか、アイデアを言い換えてください |
| 「… declined that prompt: its filter blocked the picture」 | プロバイダの安全フィルターがプロンプトか画像を止めました（Stabilityのぼかした画像や、Ideogramの安全性チェックなど）。言い換えてください |
| 「… said: … (error 400)」 | プロバイダからのメッセージを、届いたまま表示しています。FolderSkinが送ったフィールドの名前が出ていたら、報告をお願いします |
| 「the model drew a scene instead of a folder on a plain backdrop」 | フォルダ全体モードで、キーイングできる背景がありませんでした。もう一度試すか、「絵だけ」に切り替えてください。アプリはそのような画像を自分のフォルダに使うアートワークとして、自由形アイコンなら正方形の画像のまま残し、そのことを知らせます |
| 「the provider returned something that is not an image」 | 形式が不正なレスポンスか、画像ではないレスポンスが返ってきました |

## チャットアシスタントで作ったフォルダ

ChatGPTやGrokなどのチャットアシスタントでフォルダ全体を描いて、**写真を追加**で取り込むこともできます。フォルダを、単色の#FF00FFの背景か、透明な背景の上に描くよう頼んでください。FolderSkinはどちらも認識し、自分のフォルダにもう一度はめ込むことはせずに、切り抜いて余白を詰めたうえで、画像をそのままアイコンとして使います。それ以外の画像は、テンプレート用のアートワークとして扱われます。正確なルールは[ARCHITECTURE.md](../ARCHITECTURE.md#artwork-or-a-finished-folder)にあり、マゼンタの紙の上にあるものの写真が、なぜ普通の画像のまま扱われるのかも説明しています。

## 生成したスキンの保存

生成したスキンは、取り込んだ画像と同じように、届いた瞬間にプロバイダ、モデル、プロンプト、そしてどの形向けに作ったかと一緒に保存されます。再起動後もギャラリーのマイスキンにあり、そこで削除するとディスクからも消えます。ファイルの保存場所は[ARCHITECTURE.md](../ARCHITECTURE.md#saved-skins)にあります。書き込みに失敗しても（ディスクがいっぱいの場合など）、スキンは失われず、そのセッションの間は残ります。

何から作ったかも、スキンのインデックスの`recipe`に記録されます。そのため、結果をプロンプトまでたどって、もう一度作ることができます。記録されるのは、送ったとおりのプロンプト、ネガティブプロンプト（受け付けるプロバイダの場合）、スタイル、描き込む文字、それぞれの画像の役割とそのハッシュ、テンプレートとそのバージョン（`mac-folder/1`）、キーカラー、そしてレシピのバージョンです。

チャットは、ほかの画面を見ている間も、言葉と画像をそのまま保ちます。まだ作っている途中の画像も同じです。FolderSkinをもう一度開くと、新しいチャットが始まります。以前のチャットはチャットの一覧にあり、どれもそのチャットの形のままです。

生成したスキンをみんなと共有するには、コミュニティパックにします。タグを付けてアプリの**コミュニティで共有**を使うか、保存したレンダリング画像のフォルダを`folderskin-tools packs make`でパックにしてください。どちらの方法も[PACKS.md](PACKS.md)で説明しています。画像がフォルダにどう載るかは[SKINS.md](SKINS.md)をご覧ください。
